# deploy — Helm chart (ADR-020 delivery contract)

`grizzly-platform`'s Flux `HelmRelease` for this app renders `./deploy` (see `kubernetes/apps/grizzly-gameservers/` over there). This is where the bot/agent workload, its ServiceAccount, and app-level wiring live.

`templates/deployment.yaml` is the bot/agent Deployment. `templates/service.yaml` is the ClusterIP Service fronting the bot's in-game agent endpoint (port `9360`, the `@Gary` reverse loop). `templates/externalsecrets.yaml` syncs the bot/agent credentials from 1Password into namespace-local Secrets via the `onepassword` `ClusterSecretStore` — toggle with `externalSecrets.enabled` in `values.yaml`. It renders eight ExternalSecrets: `discord-bot` and `ollama-api` (`gameservers-discord/*`, `gameservers-ollama/api_key`), `grizzly-gameservers-db`, `grizzly-gameservers-kv-cache` and `grizzly-gameservers-s3` (foundation-store grants under `stores-grizzly-gameservers/*` and `stores-kv-cache/password`, for the Postgres registries, Gary's deferred-task queue and world backups), `grizzly-gameservers-ingame` (the shared in-game agent bearer token, `gameservers-ingame/token`), `grizzly-gameservers-operator` (the operator harness token, `gameservers-operator/token`), and `grizzly-gameservers-langfuse` (the turn-telemetry key pair, `gameservers-langfuse/{public_key,secret_key}`). The Deployment consumes those Secrets and never talks to the secret store directly.

Sync is `refreshPolicy: OnChange` rather than polling, because 1Password meters requests per account — so **rotating a credential takes two actions**: update the item in 1Password *and* touch the ExternalSecret so it re-reads. Updating 1Password alone changes nothing.

The two bearer tokens are separate on purpose and degrade differently. The in-game one is mounted into every game pod in this namespace, so without it the trigger route still runs, protected by NetworkPolicy alone. The operator one reaches Gary's full admin tool surface and can pre-approve destructive actions, so without it the `/operator/*` routes are not mounted at all. Those routes are reachable only over `kubectl port-forward` to the ClusterIP Service — never a NodePort or Ingress.

Agones is packaged as a standalone gated `HelmRelease` rather than a Helm dependency of this chart (see [ADR-001](../docs/decisions/001-agones-packaging.md)); it and the `cluster/` guardrails + Kyverno carve-out are wired separately, not through this chart.
